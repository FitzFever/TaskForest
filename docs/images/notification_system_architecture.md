# 通知系统架构图

*注意：本文档提供通知系统架构的文本描述，可用于生成实际的架构图。*

## 系统组件

1. **客户端应用**
   - 用户与通知系统的主要交互点

2. **通知UI组件**
   - `NotificationBell.tsx` - 显示通知图标和未读计数
   - `NotificationList.tsx` - 显示通知列表和操作按钮

3. **通知状态管理**
   - `notificationStore.ts` - 使用Zustand管理通知状态
   - 提供状态持久化，确保页面刷新后保留通知

4. **通知处理服务**
   - `notificationHandlerService.ts` - 创建和处理不同类型的通知
   - 提供桌面通知集成

5. **通知调度服务**
   - `notificationSchedulerService.ts` - 管理定时通知检查
   - 提供定期任务截止日期检查和每日摘要

6. **API服务层**
   - `notificationService.ts` - 与后端API通信
   - 提供CRUD操作和通知设置管理

7. **后端API**
   - `/api/notifications` - 通知相关的API端点
   - 处理通知创建、读取、更新和删除操作

8. **数据库**
   - 存储通知数据和用户通知设置

## 数据流

1. **通知生成流程**
   - 事件触发 -> 通知处理服务 -> 状态管理 -> UI组件 -> 用户

2. **用户操作流程**
   - 用户操作 -> UI组件 -> 状态管理 -> API服务 -> 后端API -> 数据库

3. **定时检查流程**
   - 调度服务 -> 定时触发 -> 通知处理服务 -> 通知创建

## 组件交互

```
客户端应用 <-> 通知UI组件 <-> 通知状态管理 <-> 通知处理服务 <-> API服务层 <-> 后端API <-> 数据库
                                ^                    ^
                                |                    |
                                +---- 通知调度服务 ---+
```

## 关键特性

1. **分层架构**
   - 清晰的关注点分离，便于维护和扩展

2. **离线支持**
   - 本地状态管理确保即使在网络不稳定时也能显示通知

3. **多渠道通知**
   - 支持应用内和桌面通知

4. **定时处理**
   - 自动检查和发送提醒通知

5. **用户控制**
   - 完全可定制的通知设置
